## How to read a row

| Class | Meaning | Resolution shape |
|---|---|---|
| `R` | **placement** — the conflict is *where* our code sits, so it can leave the file | move the fork's block to the named seam; the file then merges upstream-clean |
| `S` | **semantic** — both sides changed the same logic | reconcile by hand, in place; no extraction removes the overlap |
| `A` | **add/add** — created independently on both sides (git's own class) | pick a canonical copy, port the other's guarantees onto it |
| `M` | **modify/delete** — upstream removed the path (git's own class) | re-express on the replacement, or move to the fork layer |
| `F` | **file-location** — the `channel/` → `mcp-session/` rename (git's own class) | follow the rename |

**The R/S line is a rule, not a mood.** `A`, `M` and `F` are git's own `CONFLICT` class, parsed from the merge output — not a heuristic. For the 86 `content` rows the test was: *does the fork's change contain a unit that upstream does not have and that can live outside the file?* measured as (i) fork-added top-level declarations absent from the upstream version (`git diff -U0 base..main -- <file>` scanned for `export|function|class|const|interface`) and (ii) how many upstream-owned lines the fork deletes. Additions with no deleted upstream line, or a named policy unit, make an `R`; deletions inside upstream's own functions make an `S`, because a deletion cannot be relocated as a block.

**Seam names are proposals, and S2 is where they get falsified.** Every `R` names a real or clearly-shaped target (`packages/cli/src/fork/` exists with 27 files today: `server/`, `middleware/`, `routes/`, `config/`, `failover.ts`, `session-budget.ts`). Upstream has never written a line in `packages/cli/src/fork/` (0 commits), which is what makes the seam free: a fork-owned file cannot conflict with a file upstream never touches.

**`moved lines` is an estimate, and its basis is stated**: for `R` rows it is the fork's added-line count on that file (`git diff --numstat`), i.e. an upper bound on what a move has to carry. It is not a measurement of what the move will cost — S2 publishes that.

**`test that proves it` is discovered, not invented**: a `*.test.ts(x)` whose quoted import specifier resolves to that module's basename, in the working tree. 22 of the source rows have **no direct importer** — that is not the same as untested (an e2e can cover a module it never imports), but it does mean an `R` cut on those files needs a pin **before** the move, not after. Rows whose class is `R` and whose test cell reads `none today` are named in that light, not as free wins.

## What this table does NOT claim

- **`R` is not a promise that the conflict disappears.** It is a promise that the fork's edit can leave the file. S2 measures the drop on the files it touches; S5 decides whether the class-`R` population shrinks fast enough to justify the path.
- **`blocked` is absent by design.** Whether a disjoint upstream commit depends on a conflicted predecessor is S3's per-commit cherry-pick walk. S0 refuses to proxy it, and this table does not inherit a proxy.
- **Churn counts commits, not lines.** A high upstream count can be tidying. Read it next to the line deltas, which are in the evidence column.
- **The rename is load-bearing.** Three of the 122 rows exist only because upstream renamed `channel/` to `mcp-session/`; an instrument with `diff.renames=false` reads 119 and silently loses them (recorded in `scripts/sync-cost.py`'s docstring).
